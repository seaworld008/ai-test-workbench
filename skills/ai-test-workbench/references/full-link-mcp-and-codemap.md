# Full-Link System MCP Hub & Self-Evolving Code Map (v3.0)

This guide defines how **AI Test Workbench (`v3.0`)** connects browser execution to backend logs, metrics, crashes, databases, middleware, and performance budgets using a **6-Pillar Read-Only MCP Topology** and a **Self-Evolving Living Code Map (`knowledge/code-map.json` + `knowledge/SYSTEM_MAP.md`)**.

## 1. The 6-Pillar Full-Link MCP Architecture

| Pillar | Built-in Presets (`aitest mcp add`) | Enforced Read-Only Guardrail (`aitest mcp doctor`) |
|---|---|---|
| **1. Browser / UI / CDP** | `playwright-test`, `chrome-devtools` | `TEST_ALLOWED_HOSTS` + `TEST_BLOCKED_ENDPOINTS` + `serviceWorkers: 'block'` |
| **2. Observability & Crashes** | `grafana`, `prometheus`, `loki`, `sentry` | `mcp-grafana --disable-write`; PromQL/LogQL/Sentry read-only token queries |
| **3. Database State Verification** | `postgres-readonly`, `mysql-readonly` | Read-only SQL role; `ALLOW_INSERT/UPDATE/DELETE_OPERATION="false"`; `${ENV}` placeholders |
| **4. Middleware & Cache** | `redis-readonly` | `redis-mcp-server --readonly` |
| **5. Performance & Load Testing** | `k6` (+ `aitest perf` CDP Web Vitals) | Budget assertions in `perf-budget.json`; read-only GET benchmarks by default |
| **6. API Schema & Contract** | `openapi-contract` | Read-only OpenAPI/Swagger spec inspection for drift detection |

## 2. Self-Evolving Living Code Map Loop (`explore` → `map` → `run` → `diagnose`)

1. **`aitest map --target <repo>`** scans host repository source code (`Next.js`, `Vue`, `React`, `Java Spring`, `Express/NestJS`, `FastAPI`, `PHP`, `Prisma`, `SQL`)—including flagging missing lazy-loaded router chunks (`broken-route-import`)—and fuses:
   - `reports/system-topology.json` (runtime routes, portals, table headers, waterfall & malformed-query detectors)
   - `reports/results.json` (pass/fail history per spec)
   - `reports/perf-report.json` (CDP TTFB/FCP/LCP/CLS/DOMNodes & API P95/RPS)
2. Every run of `aitest explore`, `aitest run`, `aitest perf`, or `aitest map` increments `revision` inside `knowledge/code-map.json`, regenerates `knowledge/SYSTEM_MAP.md`, and non-destructively refreshes `autoGenerated: true` rules inside `impact-map.json` while preserving manual rules.
3. **Trace-Correlated Diagnostics (`aitest diagnose`)**: `tests/fixtures/base.ts` passively captures `traceparent`, `x-trace-id`, `x-request-id`, `sw8`, `eagleeye-traceid`, and exact `[startedAt, finishedAt]` failure windows, letting `diagnose` output mapped frontend/backend source files plus ready-to-run Loki LogQL, PromQL, Sentry, and read-only SQL verification queries.
