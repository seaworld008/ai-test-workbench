# 7 大支柱全链路 MCP 中枢与活体代码地图规范 (v4.0)

> [English Version](./full-link-mcp-and-codemap.en.md) · [SKILL.md](../SKILL.md)

本文档定义 **`ai-test-workbench` v4.0** 如何将浏览器端执行与原生编排工具、后端日志、监控指标、异常追踪、只读数据库、中间件缓存、性能压测与活体代码知识图谱（`knowledge/code-map.json` + `knowledge/SYSTEM_MAP.md`）打通。

## 1. 7 大支柱全链路只读 MCP 架构

| 支柱域 | 内置预设 (`npx ai-test-workbench@6.0.0 mcp add`) | 强制只读安全护栏 (`npx ai-test-workbench@6.0.0 mcp doctor`) |
|---|---|---|
| **1. 原生编排中枢 (`orchestrator`)** | `ai-test-workbench` | 原生 `mcp-serve`（`stdio` / `/mcp` / `/sse`），返回 `structuredContent` |
| **2. 浏览器 / UI / CDP** | `playwright-test`, `chrome-devtools` | `TEST_ALLOWED_HOSTS` + `TEST_BLOCKED_ENDPOINTS` + `serviceWorkers: 'block'` |
| **3. 可观测与崩溃链路** | `grafana`, `prometheus`, `loki`, `sentry` | `mcp-grafana --disable-write`；PromQL / LogQL / Sentry 只读权限 Token |
| **4. 数据库状态校验** | `postgres-readonly`, `mysql-readonly` | 只读 SQL 角色；`ALLOW_INSERT/UPDATE/DELETE_OPERATION="false"`；禁止硬编码密码 |
| **5. 中间件与缓存** | `redis-readonly` | `redis-mcp-server --readonly` |
| **6. 性能与压测** | `k6` (+ `npx ai-test-workbench@6.0.0 perf` CDP Web Vitals) | `perf-budget.json` SLO 门禁；默认仅对只读 GET 做并发基线 |
| **7. API 契约漂移** | `openapi-contract` | 只读抓取 OpenAPI / Swagger Schema 校验契约一致性 |

## 2. 活体代码知识地图闭环 (`explore` → `map` → `run` → `diagnose`)

1. **`npx ai-test-workbench@6.0.0 map --target <repo>`** 静态扫描宿主代码（Next.js、Vue、React、Java Spring、Express/NestJS、FastAPI、PHP、Prisma、SQL）—— 包含懒加载路由断链检测（`broken-route-import`）—— 并持续融合运行态 `system-topology.json`、`results.json` 与 `perf-report.json`。
2. 每次执行 `explore` / `run` / `perf` / `map` 均会自动递增 `revision` 并刷新 `SYSTEM_MAP.md`，同时非破坏式同步 `impact-map.json` 中的 `autoGenerated` 规则（保留手工规则）。
3. **Trace-ID 根因贯通（`npx ai-test-workbench@6.0.0 diagnose`）**：`base.ts` 自动捕获响应头中的分布式追踪 ID（`traceparent`、`x-trace-id`、`x-request-id`、`sw8`、`eagleeye-traceid`）与精确时间窗，在 `ai-diagnostics.md` 直接给出前端/后端源码路径与可复制的 Loki / PromQL / Sentry / 只读 SQL 查询。
