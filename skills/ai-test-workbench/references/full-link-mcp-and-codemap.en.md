# 7-Pillar Full-Link System MCP Hub & Living Code Map (v4.0)

> [简体中文 (默认)](./full-link-mcp-and-codemap.md) · [SKILL.md](../SKILL.md)

This guide defines how **AI Test Workbench (v4.0)** connects its native orchestrator MCP and browser execution to backend logs, metrics, crash reports, read-only databases, cache inspection, and the **Self-Evolving Living Code Map (`knowledge/code-map.json` + `knowledge/SYSTEM_MAP.md`)**.

## 1. The 7-Pillar Full-Link Read-Only MCP Topology

| Pillar | Built-in Presets (`npx ai-test-workbench@5.1.1 mcp add`) | Enforced Read-Only Guardrail (`npx ai-test-workbench@5.1.1 mcp doctor`) |
|---|---|---|
| **1. Native Orchestrator** | `ai-test-workbench` | Native `mcp-serve` (`stdio` / `/mcp` / `/sse`) returning `structuredContent` |
| **2. Browser / UI / CDP** | `playwright-test`, `chrome-devtools` | `TEST_ALLOWED_HOSTS` + `TEST_BLOCKED_ENDPOINTS` + `serviceWorkers: 'block'` |
| **3. Observability & Crashes** | `grafana`, `prometheus`, `loki`, `sentry` | `mcp-grafana --disable-write`; PromQL/LogQL/Sentry read-only token queries |
| **4. Database State Verification** | `postgres-readonly`, `mysql-readonly` | Read-only SQL role; `ALLOW_INSERT/UPDATE/DELETE_OPERATION="false"`; `${ENV}` placeholders |
| **5. Middleware & Cache** | `redis-readonly` | `redis-mcp-server --readonly` |
| **6. Performance & Load Testing** | `k6` (+ `npx ai-test-workbench@5.1.1 perf` CDP Web Vitals) | Budget assertions in `perf-budget.json`; read-only GET benchmarks by default |
| **7. API Schema & Contract** | `openapi-contract` | Read-only OpenAPI/Swagger spec inspection for drift detection |

## 2. Self-Evolving Living Code Map Loop (`explore` → `map` → `run` → `diagnose`)

1. **`npx ai-test-workbench@5.1.1 map --target <repo>`** scans host repository source code (`Next.js`, `Vue`, `React`, `Java Spring`, `Express/NestJS`, `FastAPI`, `PHP`, `Prisma`, `SQL`)—including flagging missing lazy-loaded router chunks (`broken-route-import`)—and fuses runtime `system-topology.json`, `results.json`, and `perf-report.json`.
2. Every run increments `revision`, regenerates `knowledge/SYSTEM_MAP.md`, and non-destructively refreshes `autoGenerated` rules inside `impact-map.json`.
3. **Trace-Correlated Diagnostics (`npx ai-test-workbench@5.1.1 diagnose`)**: Passively captures distributed trace headers and outputs mapped frontend/backend source files plus ready-to-run Loki, PromQL, Sentry, and read-only SQL verification queries.
